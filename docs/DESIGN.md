## 二、算法设计

### 5 策略权重合成

每个号码的"被选概率"由 4 部分加权：

```
权重 = a × 历史频次占比
     + b × 是否用户偏好
     + c × 是否环境数字
     + d × 随机
     + 因素库加成
     - if 排除数字 then × 0.05
```

5 个固定策略：

| 策略 | a | b | c | d | 特点 |
|------|---|---|---|---|------|
| A 重热度 | 4 | 1 | 1 | 1 | 看历史 |
| B 重偏好 | 1 | 4 | 1 | 1 | 看用户输入 |
| C 重环境 | 1 | 1 | 4 | 1 | 看日期/环境 |
| D 重运气 | 1 | 1 | 1 | 4 | 主要随机 |
| E 均衡 | 1 | 1 | 1 | 1 | 平均 |

**为什么选这种结构**？
- 把"用户输入"作为独立维度（b），让用户偏好有清晰位置
- 保留历史频率（a），不放弃"数据驱动"
- 环境数字（c）作为弱信号
- 随机（d）保证不会完全可预测

### 因素库（lucky-pick 扩展）

每个因素有统一接口：

```js
{
  type: 'lucky' | 'avoid' | 'date' | 'zodiac' | 'dream' | 'lifepath' | 'custom',
  label: string,
  weight: number,          // 因素自身权重 0-1
  data: any,
  contains: (n) => boolean // 判断数字 n 是否被该因素"包含"
}
```

**设计原则**：
- 每个因素都是独立对象，互不耦合
- 可以叠加任意多个因素
- 算法统一处理"被因素包含则加分"

### 抽样算法

采用 **Efraimidis-Spirakis 不放回加权抽样**：

```
key = -ln(u) / weight
按 key 升序取前 k 个
```

比简单"按权重随机抽一个剔除"更公平，避免极端情况（连续抽到同一批）。

## 三、PWA 设计

### 为什么是 PWA？

**对比表**：

| | PWA | 小程序 | 原生 App |
|---|-----|--------|---------|
| 跨平台 | ✅ | ⚠️ 平台特定 | ❌ 多版本 |
| 无需审核 | ✅ | ❌ | ❌ |
| 离线 | ✅ | ⚠️ | ✅ |
| 添加到桌面 | ✅ | ❌ | ✅ |
| 体积 | 1-3 MB | 几 MB | 30-80 MB |
| 推送通知 | Android ✅ iOS ❌ | ✅ | ✅ |

PWA 几乎就是"网页版的小程序"，对本产品的"娱乐工具"定位**最优**。

### Service Worker 策略

**HTML 走 network-first**（保证最新）
**静态资源走 cache-first**（保证离线）

```js
if (是 HTML) {
  fetch(网络).catch(用缓存)  // 优先拿新
} else {
  caches.match(缓存) || fetch(网络)  // 优先用缓存
}
```

### 开发模式禁用 SW

```js
if (location.hostname === 'localhost' || '127.0.0.1') {
  // 不注册 SW，避免开发时缓存干扰
  // 主动注销已有 SW
}
```

部署到生产（HTTPS）后才注册 SW。

## 四、UI 设计

### 设计语言：**柔和中性**

**视觉原则**：
- 暖色基调（赤陶色 #D97757），不用冷色不用黑白灰
- 柔和圆角（10-16px）+ 浅阴影
- 宽松间距，呼吸感
- 移动优先

**为什么是赤陶色**？
- "幸运""温暖"的色彩隐喻
- 不会太卡通（不像儿童 App）
- 不会太严肃（不像办公工具）
- 跟"彩票""玄学"有一定调性契合，但不刻板

## 五、数据策略

### 不抓数据（短期）

**当前**：复用原项目抓的 558 + 560 期历史数据
- 截止 2026-09-18
- 不会自动更新

### 半自动抓（中期）

```bash
# 用户偶尔跑一次
node src/fetch_data.mjs
# 自动更新 data/dlt.js 和 data/qxc.js
# 然后 git push
# 用户打开页面看到新数据
```

### 全自动抓（长期）

部署 Cloudflare Worker：
- 每天定时调 Worker
- Worker 抓最新开奖数据
- 存到 KV 存储
- 用户打开页面 → 拉最新数据

## 六、设计上踩过的坑

### 1. SW 缓存导致开发期看不到新版本

**问题**：SW 缓存了 HTML，浏览器一直用旧版本
**解决**：开发模式禁用 SW

### 2. 相对路径 `../data/` 在 in-app browser 加载失败

**问题**：Codex 内置浏览器对 `../` 路径解析有 bug
**解决**：把 data/ 复制到 public/data/，用相对路径 `data/`

### 3. 因素库接口要兼容原算法

**问题**：原 engine.mjs 只接受 `Set<number>` 类型的 lucky/avoid
**解决**：在算法层加 `factorsToSets()` 适配层，把新因素库转成原算法格式

### 4. 用户体验比算法更重要

**认知**：用户不懂算法，只在乎"我加的东西有没有影响结果"
**设计**：让权重滑块可见、让策略名（重偏好/均衡）显示出来
